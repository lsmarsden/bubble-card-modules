Progress reading

Progress source + options in → percent, and a ticker that always repaints with the latest config

numeric source · start/end scaling
timer: active / paused
override · invert · clamp
ticker lifecycle (one owner)

Problem

The Progress concept is split across three shallow helpers and re-implemented inline. The ticker's interval key leaks across the seam, and its closure goes stale. Verified: switch a condition to a second config on the same active timer and the border repaints green, then reverts to the first config's red within one second. The Separator re-implements value parsing and silently lacks start/end and timer support.

Solution

Pull value resolution, timer progress, override/invert/clamp and ticker ownership behind one Progress reading module. Both progress modules call it, and only it knows the interval key.

Wins

  • locality: stale-ticker bug fixed once
  • leverage: Separator gains timers, start/end
  • interval key stops leaking
  • tests hit one interface with fake timers
  • delete timer.js + timerUpdater.js as modules

Module build

Module folder in → artifact YAML out. Import resolution, helper inclusion and wrapping are internal.

internal: bundler (off-the-shelf or the existing extractor) · YAML assembly · validation

artifact YAML✓ artifact tests eval the built code against the same card fixtures

Problem

The build is a hand-rolled, regex-based tree-shaker. It is shallow toward its own tests: extractors.ts imports modulesDir from build_modules.ts, which runs the whole build at import, so extractors.ts has no tests. Verified: the icon_border_progress artifact ships a stray top-level copy of getDashArray, an inner closure of createProgressBorder, with unbound free variables. Helpers can't share top-level constants or classes.

Solution

Pull "module folder → artifact" behind one module with no import-time side effects. Run each module's integration fixtures against the built code, so a regression in what users install fails CI.

Wins

  • tests cross the shipped seam
  • import cycle removed
  • locality: bundling bugs surface in CI
  • regex extractor becomes deletable
  • helpers may share constants and classes

After: the seam is real; it has two adapters

Corrected after checking upstream Bubble Card v3.4.3: hass is a documented scope name for code:, not a build accident. The seam is still invisible in helper interfaces, which is the friction here.

Problem

Every helper that touches entity state depends on a hass that appears in no interface. Production gets it from Bubble Card's documented code: scope (a tracking proxy, v3.4.3); tests get it by mutating global. Four integration test files each rebuild the same card DOM, getComputedStyle stub and hass states.

Solution

Make entity-state access a named seam with two adapters: Bubble Card's hass in production, a shared Card harness in tests. Keep the per-call ergonomics of getState.

Wins

  • hidden dependency enters the interface
  • two adapters justify the seam
  • one fixture, four test files
  • pairs with #2 artifact tests
